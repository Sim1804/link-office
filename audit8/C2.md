# C2 — Délai du classifieur de sécurité (E06)

## 1. Contexte et lecture du code existant

- **Fichiers concernés** : `src/lib/iris/safety.ts` et `.env.example`
- **Lignes incriminées dans `src/lib/iris/safety.ts`** : `199-201`

### Extrait du code avant correction :
```typescript
199:   const controller = new AbortController();
200:   const timeoutId = setTimeout(() => controller.abort(), 1500);
```

### Problème identifié :
1. Le timeout du classifieur de sécurité était fixé en dur à `1500` ms (1,5 s), alors que les mesures en conditions réelles donnent un P95 à 4,4 s et un P99 à 5,5 s. Ce délai trop court provoquait des coupures prématurées.
2. La variable d'environnement `IRIS_CLASSIFIER_TIMEOUT_MS` n'était ni lue par `classifyWithLLM`, ni documentée dans `.env.example`.
3. Le repli fermé (Fail-Closed vers 3114/15) devait être vérifié pour 5 conditions d'échec :
   - Expiration du délai (timeout)
   - Erreur API (HTTP 500 ou erreur réseau)
   - Dépassement de quota / rate limit API (HTTP 429)
   - Confiance insuffisante du modèle (< 0,70)
   - Erreur d'analyse de la réponse JSON (parse error / sortie non JSON)

---

## 2. Solution implémentée
1. Modification de `classifyWithLLM` dans `src/lib/iris/safety.ts` pour lire `process.env.IRIS_CLASSIFIER_TIMEOUT_MS`, avec une valeur par défaut tolérante de 10 000 ms (10 s) en l'absence de variable.
2. Documentation dans `.env.example` de la variable `IRIS_CLASSIFIER_TIMEOUT_MS=8000` avec le commentaire explicatif `# Délai max du classifieur de sécurité IRIS (au-dessus du P99 mesuré de 5,5 s)`.
3. Suite de tests unitaires dédiée `tests/iris/classifier-timeout-failsafe.test.ts` couvrant l'ensemble des 5 conditions d'échec et la configurabilité du timeout.
