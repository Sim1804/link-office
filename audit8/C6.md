# C6 — Limite Freemium appliquée côté serveur (T7.3)

## 1. Contexte et Problème
L'audit de la passe 7 (`audit7/T7_3_reco_plans.md`) a établi que la persistance en base de données stocke l'intégralité des recommandations générées (5 recommandations, micro-défis et partenaires), mais que la restriction pour les utilisateurs de l'offre Freemium (3 recommandations et 3 micro-défis) n'était appliquée que tardivement dans les composants d'affichage frontend (`app/resultats/[userId]/page.tsx`, `DashboardOrdonnanceTab.tsx`).

Les routes API renvoyant les ordonnances (`app/api/ordonnances/[userId]`, `app/api/resultats/[userId]`) renvoyaient la totalité des éléments en clair dans leur payload JSON à n'importe quel client authentifié, y compris Freemium. De plus, la route canonique `app/api/assessment/[id]/prescription/route.ts` n'existait pas.

### Fichiers concernés
- `src/lib/iqrh/prescription-service.ts` (l. 407-417 avant modification)

## 4. Correctifs Appliqués
1. **Méthode `PrescriptionService.filterForUserPlan(prescription, userId)`** :
   - Lecture du statut d'abonnement directement en base (`prisma.user.findUnique`), et non dans la session ou les cookies.
   - Contrôle du cycle de vie de la campagne : si la campagne associée est expirée (`endDate < now`) ou fermée (`status: "CLOSED"`), le compte est automatiquement traité côté serveur comme `FREEMIUM`.
   - Pour un compte `FREEMIUM` : filtrage strict limitant le résultat à au plus 3 recommandations et 3 micro-défis.
   - Pour un compte `PREMIUM` ou `PREMIUM_PLUS` : restitution intégrale de l'ensemble des éléments persistés (ex: 5 recommandations + 5 micro-défis).
   - Préservation stricte de la persistance BDD (aucun élément supprimé en base).
2. **Filtrage sur les routes existantes** :
   - Mise à jour de `app/api/ordonnances/[userId]/route.ts` pour filtrer la prescription avant restitution JSON.
   - Mise à jour de `app/api/resultats/[userId]/route.ts` pour filtrer `userResult.prescription` avant restitution JSON.
3. **Création de la route `app/api/assessment/[id]/prescription/route.ts`** :
   - Permet l'interrogation par `assessmentId` ou `userId`.
   - Contrôle d'authentification (`auth()`) et d'autorisation (propriétaire ou superadmin).
   - Application du filtrage serveur selon le plan réel en BDD.

+  /**
+   * Filtre côté serveur les éléments d'une ordonnance selon le statut d'abonnement réel
+   * de l'utilisateur (lu en base de données, avec repli Freemium si la campagne est expirée).
+   * 
+   * Règle Freemium : au plus 3 recommandations et 3 micro-défis.
+   * Règle Premium / Premium+ : l'ensemble des éléments persistés.
+   * 
+   * @param prescription - L'ordonnance relationnelle avec ses `items`
+   * @param userId - L'identifiant de l'utilisateur concerné
+   */
+  static async filterForUserPlan<T extends { items?: any[] }>(prescription: T, userId: string): Promise<T> {
+    if (!prescription || !Array.isArray(prescription.items)) {
+      return prescription;
+    }
+
+    const dbUser = await prisma.user.findUnique({
+      where: { id: userId },
+      select: {
+        id: true,
+        subscription: true,
+        campaignId: true,
+        campaign: {
+          select: {
+            endDate: true,
+            status: true,
+          },
+        },
+      },
+    });
+
+    let currentTier = dbUser?.subscription || "FREEMIUM";
+
+    // Vérification campagne : si expirée ou fermée en base, traitement comme FREEMIUM
+    if (dbUser?.campaign) {
+      const isExpired = dbUser.campaign.endDate && new Date(dbUser.campaign.endDate) < new Date();
+      const isClosed = dbUser.campaign.status === "CLOSED";
+      if (isExpired || isClosed) {
+        currentTier = "FREEMIUM";
+      }
+    }
+
+    const isPremium = currentTier === "PREMIUM" || currentTier === "PREMIUM_PLUS";
+    if (isPremium) {
+      return prescription;
+    }
+
+    // Filtrage Freemium : max 3 recommandations et max 3 micro-défis
+    const recommendations = prescription.items
+      .filter((item: any) => item.kind === "RECOMMENDATION")
+      .slice(0, 3);
+
+    const microChallenges = prescription.items
+      .filter((item: any) => item.kind === "MICRO_CHALLENGE")
+      .slice(0, 3);
+
+    const otherItems = prescription.items
+      .filter((item: any) => item.kind !== "RECOMMENDATION" && item.kind !== "MICRO_CHALLENGE");
+
+    return {
+      ...prescription,
+      items: [...recommendations, ...microChallenges, ...otherItems],
+    };
+  }
