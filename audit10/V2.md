# Audit 10 — Tâche V2 : Cloisonnement du module /api/actions et correction du détecteur cross-tenant

**Date** : 2026-10-18  
**Branche** : `fix/passe10`  
**Verdict global** : **CONFORME** (après application du correctif et correction du détecteur de la matrice)

---

## 1. CONSTAT

### 1.1 Examen des réponses de la matrice signalées « Novatech »
Dans la passe 8 / 9, les cellules suivantes pour `CROSS_ADMIN` (Béatrice Lambert, organisation `cmuyj281v0001v6h87ao4uo9f` - Avenir Santé Mutuelle) avaient été signalées avec la mention `contientOrgA: true` :
1. `GET /api/actions`
2. `POST /api/actions`
3. `GET /api/actions/export`
4. `POST /api/actions/suggest`

#### a) Propriétaire (`organizationId`) en base de chaque ligne renvoyée
L'interrogation de la base PostgreSQL sur les actions renvoyées à l'appelant Béatrice Lambert montre :
- Action ID : `cmvdwf3g2003mv6c8gwv0i3za`
- `organizationId` : `cmuyj281v0001v6h87ao4uo9f` (Avenir Santé Mutuelle)
- Titre : `"Plan QVT Novatech"`
- L'action appartenait bien à l'organisation de l'appelant. La détection « Novatech » était en partie un artefact du détecteur de test qui recherchait la sous-chaîne `"Novatech"` dans le corps de réponse, or le harnais de test injectait lui-même `"title": "Plan QVT Novatech"` dans le payload de test de `POST /api/actions`.

#### b) Contrôle de `campaignId` fourni dans `POST /api/actions` (Code avant correctif)
Examen de `app/api/actions/route.ts` (lignes 85-115 avant correctif) :
```typescript
const action = await prisma.actionItem.create({
  data: {
    title: parsed.data.title,
    description: parsed.data.description,
    organizationId: user.organizationId,
    campaignId: parsed.data.campaignId, // <-- AUCUNE VÉRIFICATION D'APPARTENANCE
    ...
  }
});
```
**Constat de vulnérabilité réelle** : Le champ `campaignId` était injecté directement sans vérifier si la campagne ciblée appartenait ou non à `user.organizationId`.
Un administrateur de l'Organisation B pouvait ainsi créer ou associer une action à une campagne de l'Organisation A (`camp-novatech-2026`).

#### c) Risque d'exposition dans l'export CSV
Examen de `app/api/actions/export/route.ts` :
L'export inclut la relation `campaign: { select: { title: true } }`. Si une action de l'Organisation B référençait une campagne de l'Organisation A par injection de son `campaignId`, le titre de la campagne de l'Organisation A apparaissait dans l'export CSV de l'Organisation B.

---

## 2. DÉCISION

Conformément à la règle de décision :
1. **Correctif applicatif impératif** : Refuser systématiquement (HTTP 404 `Campagne introuvable ou non autorisée`) toute tentative de référencer un `campaignId` n'appartenant pas à l'organisation de l'appelant dans :
   - `POST /api/actions`
   - `PATCH /api/actions/[id]`
   - `POST /api/actions/suggest`
2. **Correction du détecteur de la matrice T4** : Remplacer la détection par simple sous-chaîne (`ORG_A_MARKERS.some(...)`) dans `validation/t4-authz/run.ts` par une vérification structurée des champs `organizationId` et des identifiants stricts de l'Organisation A (`cmuyj280k0000v6h87dvugtq1`, `camp-novatech-2026`). Aucune attente de statut n'est modifiée.

---

## 3. CORRECTION APPLIQUÉE

### 3.1 `app/api/actions/route.ts`
Vérification systématique de la campagne si `campaignId` est fourni :
```typescript
if (parsed.data.campaignId) {
  const campaign = await prisma.campaign.findFirst({
    where: { id: parsed.data.campaignId, organizationId: user.organizationId },
  });
  if (!campaign) {
    return NextResponse.json(
      { error: "Campagne introuvable ou non autorisée" },
      { status: 404 }
    );
  }
}
```

### 3.2 `app/api/actions/[id]/route.ts`
Vérification similaire dans la méthode PATCH lors de la mise à jour éventuelle de `campaignId` :
```typescript
if (parsed.data.campaignId) {
  const campaign = await prisma.campaign.findFirst({
    where: { id: parsed.data.campaignId, organizationId: user.organizationId },
  });
  if (!campaign) {
    return NextResponse.json(
      { error: "Campagne introuvable ou non autorisée" },
      { status: 404 }
    );
  }
}
```

### 3.3 `app/api/actions/suggest/route.ts`
Vérification dans la génération de suggestions d'actions QVT :
```typescript
if (body.campaignId) {
  const campaign = await prisma.campaign.findFirst({
    where: { id: body.campaignId, organizationId: user.organizationId },
  });
  if (!campaign) {
    return NextResponse.json(
      { error: "Campagne introuvable ou non autorisée" },
      { status: 404 }
    );
  }
}
```

### 3.4 `validation/t4-authz/run.ts`
Remplacement du détecteur de fuite par sous-chaîne par la fonction `detectOrgALeak` inspectant l'`organizationId` des objets JSON retournés.
